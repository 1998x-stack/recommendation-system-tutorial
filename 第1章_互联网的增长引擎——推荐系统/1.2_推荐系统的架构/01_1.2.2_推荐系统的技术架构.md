# 推荐系统的技术架构：把数据、模型与在线服务连成可靠链路

逻辑框架说明系统要完成什么；技术架构说明这些工作如何在数据平台、训练环境和在线服务中可靠运行。推荐系统的难点不仅是模型精度，还包括事件是否可信、特征是否及时、训练与服务是否一致，以及请求能否在延迟预算内完成。

## 从一次用户行为开始：事件采集与数据契约

用户浏览、点击、加购、购买、跳过和隐藏内容时，客户端或服务端会产生事件。每条事件至少应有稳定的 **event_id**、**user_id**、**item_id**、**event_type**、事件时间和必要的请求上下文。

推荐系统尤其需要记录曝光事件：用户实际看到了哪个物品、位于哪个位置、由哪个候选源产生、使用了哪个模型和策略版本。没有曝光日志，训练数据就无法区分“用户看见但没点”和“用户从未看见”。

数据契约要明确字段类型、允许值、时区、迟到数据策略、去重键和隐私边界。事件 ID 用于幂等去重；事件时间用于还原行为发生顺序；处理时间只说明数据何时进入系统，不能代替业务发生时间。

## 批处理与流处理：速度和完整性之间的分工

数据进入日志系统后，通常会走两条互补路径：

- **流处理**：处理新近事件，更新会话状态、实时计数和在线特征，适合需要快速反映用户最新行为的场景。
- **批处理**：处理较长时间范围的历史数据，完成去重、回填、统计聚合、训练样本生成和周期性特征计算。

两条路径必须对同一特征保持一致的定义。例如“过去 7 天点击次数”需要明确按事件时间还是处理时间计算、如何处理迟到事件、是否排除重复曝光。否则离线训练看到的值与线上请求读取的值会不一致。

Lambda、Kappa 等架构名称只是组织批流处理的不同方式，不是推荐系统必须采用的固定答案。技术选型应取决于数据规模、实时性、回填能力、团队运维复杂度和一致性要求。

## 特征存储：训练时能用，服务时也必须能用

离线特征通常用于训练和评估，在线特征用于实时推断。两者需要共享特征定义和实体键，并保证时间语义一致。

一个常见风险是**未来信息泄漏**：构造某个时刻的训练样本时，误用了该时刻之后才产生的统计值。正确的 point-in-time join 应只读取样本预测时刻之前可用的特征。另一个风险是**训练—服务偏差**：离线使用精确回填数据，线上却只能读到延迟或缺失的特征。

特征平台还要监控缺失率、分布漂移、数据新鲜度、读取延迟和线上线下偏差。特征值正确但过期，同样可能导致错误推荐。

## 模型训练、发布与在线推断

一个可运营的模型生命周期通常包括：

1. 从事件和曝光日志构造训练样本，并按时间切分训练、验证和测试数据；
2. 训练模型，记录代码版本、数据版本、特征 schema、超参数和随机种子；
3. 检查离线指标、分群表现、校准、覆盖率和安全护栏；
4. 将模型注册为不可变版本，准备回滚和灰度策略；
5. 发布模型服务，并同步更新向量索引、规则和依赖的特征版本；
6. 通过线上实验验证效果，持续监控服务质量和模型质量。

召回模型可能需要预先计算物品向量并构建 ANN 索引；排序模型则通常在请求时对候选集合做实时推断。模型服务不能只返回分数，还要能追踪模型版本、特征版本、候选来源和请求耗时。

## 在线请求的延迟预算与降级路径

在线链路包括特征读取、多路召回、过滤、排序、重排和结果序列化。每一段都需要预算，而不是只监控端到端平均耗时。若一个候选源超时，系统可以跳过该源、使用缓存或回退到稳定规则；若特征缺失，应有默认值和降级策略，而不是让整个请求失败。

常见的工程指标包括 P50/P95/P99 延迟、超时率、错误率、QPS、缓存命中率、候选数量、索引版本和模型加载状态。只看平均延迟会掩盖尾部请求体验。

## 架构健康度：模型质量和系统质量一起看

| 层次 | 核心问题 | 可监控信号 |
|---|---|---|
| 事件层 | 日志完整、可去重、时间可信？ | 丢失率、重复率、迟到率、schema 错误 |
| 特征层 | 训练与线上定义一致？ | 缺失率、新鲜度、分布偏移、读取延迟 |
| 模型层 | 预测目标和人群表现稳定？ | AUC / NDCG、校准、分群差异、漂移 |
| 服务层 | 请求能否稳定返回？ | P95/P99、超时、错误率、QPS |
| 产品层 | 推荐是否改善真实体验？ | 转化、留存、负反馈、覆盖、多样性 |

系统上线后，模型质量下降可能来自数据 schema 变化、特征过期、索引未更新、流量结构变化或服务降级，而不一定是模型参数本身的问题。排障需要沿着数据到服务的完整链路追踪。

## 一个可运行的事件校验与去重示例

下面的代码展示事件时间校验和基于 event_id 的幂等去重。它要求时间戳包含时区，并将其规范化为 UTC；生产系统还需要处理迟到事件、撤回、隐私删除和跨服务 schema 演进。

~~~python
from examples.ch01.lesson_1_2_2 import deduplicate_events

events = [
    {"event_id": "e1", "user_id": "u1", "item_id": "i1",
     "event_type": "click", "event_time": "2026-11-20T10:00:00+08:00"},
    {"event_id": "e1", "user_id": "u1", "item_id": "i1",
     "event_type": "click", "event_time": "2026-11-20T02:00:00Z"},
]
print(len(deduplicate_events(events)))

~~~
